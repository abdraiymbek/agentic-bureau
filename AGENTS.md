# Bureau agent instructions

## Product UI and design

The product is **Agentic Bureau** (the licence, terms, website and social profiles) and **Bureau** everywhere else (the app, the CLI, docs and the agent conversation). Before creating or changing any user-facing surface, read [the Bureau design specification](design-system/design.md). Use [the canonical tokens](design-system/tokens.css) (semantic roles in both themes, never raw values), the vendored fonts (`design-system/fonts/bureau.css`), the pixel mark (`Mark` / `design-system/brand/`), the Bureau icons (`renderer/ui/icons.tsx`, never an icon library), and the primitives in `apps/desktop/src/renderer/ui/kit.tsx` (`Button`, `IconButton`, `Tooltip`, `ConfirmButton`, `Menu`, `Segmented`, `Field`, `Checkbox`, `QuantityField`, `State`, `Notice`, `Empty`, `Skeleton`, `Qty`, `Time`, …; `ErrorBoundary` in `ui/ErrorBoundary.tsx`). The live **Design system** view (`renderer/system/DesignSystemView.tsx`) is the component reference.

Preserve the Lens interaction model: three zoom levels (the project through one lens — Flow, Parts, Timeline, Files, Evidence → one object between its input and consequence rails → one decision), a left sidebar (the project and its census, search, Agent, Decisions, the lenses, conversations) beside one sheet that holds the work, no dashboard, causal left-to-right layout, type-shaped stages, and the agent surface (tab and floating window, session bar, activity rail from the host's call ledger) with two panes: the conversation (headless Codex or Claude Code runs with inline cards; `renderer/chat/`, `styles/conversation.css`, host side `crates/agent-host/src/chat.rs`) and the terminal wired to the real PTY. One agent works in a project at a time, and “Ask agent” follows the active pane. Keep the visual language: a Carbon window with the work on one sheet, soft frames and square pixels (the mark, the live pixel, state marks, link terminals, the layer patterns), Mona Sans interface text, JetBrains Mono values, one cyan signal reserved for the live agent, focus and the lit thread, labelled engineering state, and calm by default (detail on hover, no capitals, colour only where it means something). Dark is the default theme; light shares every role. Add a stage or a lens rather than a page: a lens is one entry in the `LENSES` registry (`renderer/project/lenses.ts`) plus its component, and the sidebar, `⌘n`, the omnibar, the preview and the catalogue read that list. Styles live in `renderer/styles/`, one file per surface, imported in cascade order by `styles/index.css`; put a rule in the file of the surface it styles. Follow the specification’s extension checklist and update the catalogue for new reusable patterns.

Preserve quantities and units, unknowns, evidence, revision history, and human review. Do not fabricate tool success, agent activity, collaboration, production readiness, or data. Keep existing `@bureau` APIs, `bureau call` / `bureau mcp`, and `.bureau` storage (schema 1, additive changes only) compatible unless the task explicitly includes migration. Projects made before the rename keep `.omenflow` and `omenflow.project.json` until Bureau opens them and renames both; recorded engine, checker and format identifiers (`omenflow-…`) are provenance and stay as written. Contracts change first in `packages/contracts` and are exported with `pnpm contracts:export`; see [CONTRIBUTING.md](CONTRIBUTING.md).

Use `pnpm design:preview` for disposable populated design review: it runs the real renderer on the Rust headless host (`apps/headless`, `bureau-host`) with the rover and drone fixtures, and its Agent tab runs a real terminal and real conversation sends (a Custom CLI; Codex CLI and Claude Code only with `BUREAU_PREVIEW_AGENTS=1`, since they spend model credits and may update themselves; without it, terminals and conversation sends are refused). Use `pnpm dev` for native desktop validation. See `design-system/verification.md` for the latest checks and limits.

## Videos

`videos/` is a standalone npm package (not a pnpm workspace member) holding the launch film and the earlier trailer. Both are deterministic HTML compositions: every property is a function of time alone, using the canonical tokens, `design-system/fonts/fonts.css` (still Geist and IBM Plex Mono: the films move to the Bureau brand in their own pass), Phosphor icons and Sable rover fixture data. Run `npm install` in `videos/`, then `npm run preview` (scrubbable, space to play; it prints both URLs).

- **Launch film** (`videos/launch/`, 29 s, 16:9 and 9:16): the shot list and its truth, brand and colour rules are in `videos/launch/STORYBOARD.md`. `scenes/index.js` holds the timeline; each scene is one file (`scenes/<id>.js`) that lays out both formats, with shared helpers in `launch/lib/` (the thread, kinetic type, the procedural rover and its point-cloud stage, the Flow map, line fields). `npm run render:launch` (needs Homebrew `ffmpeg`) writes `videos/omen-flow-launch.mp4` and `videos/omen-flow-launch-vertical.mp4`. For review, `node scripts/render.mjs --comp launch --draft [--range 4,12] [--only <ids>] [--silent]` renders a quick 30 fps slice to `out/`, and `node scripts/sheet.mjs --comp launch [--format 9x16] --step 0.25 --out <dir>` writes labelled contact sheets. The score is synthesised by `scripts/launch-audio.mjs` (instruments in `scripts/synth.mjs`) from a cue table at its top; retime it with the picture.
- **Trailer** (`videos/trailer/`, 18.5 s): `npm run render` writes `videos/omen-flow-trailer.mp4`; `node scripts/render.mjs --draft` renders a quick 30 fps version to `out/`, and `--still 5.6,9.1 --still-dir /tmp/x` exports PNG frames. Its soundtrack is `scripts/audio.mjs`.

The root `.prettierignore` excludes `videos/`; it keeps its own formatting.
