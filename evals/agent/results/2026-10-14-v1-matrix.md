### What the profile changed (Claude haiku, compact against full)

Pass and fail were identical in all four tasks; cost was not. Per model turn
the full profile (57 tools listed) carried more input than compact (13
tools): 15k vs 21k (requirements), 22k vs 47k (cad-plate), 24k vs 45k
(calculation), 28k vs 58k (finish-discipline) tokens per turn. Total input
was 22 % to 76 % lower in compact.

The profile also changed which form of `cad_check` expectation a model
wrote, and that decided task d's cost: every session shown the compact
schema overlay (compact and standard list it) used the short form
(`size`, `bodies`, `holes`) and matched the seeded committed scope on the
first try (haiku compact, sonnet, luna); every full-profile session wrote the
long form (`sections`, `shells`) and got `scope_changed` at least once
(haiku full 7 times, opus and astra once). The long form drops the empty
point the short form derives at each hole, and no agent tool shows what the
committed expectations were. The seed used the short form, so this favours
the overlay here; a seed committed in long form would penalise it instead.

## Not fixed here (outside this track's files)

1. **Committed expectations are invisible to an agent.** A `scope_changed`
   reply and the gate's `cad_check_failed`/`cad_scope_changed` items say which
   keys changed and "restore the committed assertions", but no agent tool
   returns those assertions (`next.args` carries only `artifactId`). This
   cost haiku full 9 checks, 1.05M input tokens and 154 s on a one-line edit,
   and opus and astra one extra check each. Fix in the core: return the
   committed normalised `expect` in those replies and in `next.args`.
2. **The core stores any unit string** in artifact payloads (`"degree"`,
   `"minutes"`, `"grams"` were all accepted in a probe); only calculations
   check units. The new agent-side warning names them; the core (or
   `parse_agent_input`) should reject or normalise them with the unit
   parser's repair.
3. **`battery_energy` invites a guess**: its required `usable_fraction` input
   is described "e.g. 0.8 for 80% DoD" (`power_budget.margin` has "e.g.
   1.25"). Make such inputs optional with a recorded default of 1 and an
   assumption, or drop the example value.
4. **`project_summary.next`** on a project without requirements says "No
   requirement is recorded yet; topic requirements shows how to capture
   them"; one model read it as an instruction while asked for a part.

- The harness's CAD check uses the product's checker on the product's

### What the fixes changed, by cause

- **Committed expectations (K1)** decided all three finish-discipline cells.
  All three sent exactly the committed normalised expectations the gate
  item now carries: `size [40, 24, 20]`, `shells 1`, `empty [[0, -4, 2]]` and
  a z = 2 section with a 6 mm hole at (0, −4). Across the three runs,
  `scope_changed` came back 0 times in 5 checks, against 9 times in 15 in
  the first pass. Input tokens fell 74 % for haiku full, 25 % for opus and
  45 % for astra. The profile effect noted under "What the profile changed"
  (long-form expectations drift from a short-form committed scope) no longer
  costs anything here, because neither form has to be rebuilt from scratch.
- **Template default (K3)**: both calculation runs used the template without
  inventing `usable_fraction`. The result is 3.33 Wh, and its dependence on
  the default is recorded as an assumption, not hidden. The model's own
  choice no longer decides the outcome: before this fix the same playbook
  gave 0.8 in 1 of 3 re-runs.
- **Units (K2)** was not exercised. Both requirement runs wrote the symbol
  in the first call, as both `fix-1` runs did, so the agent-layer
  instruction was enough. The core's normalisation and `INVALID_UNITS` refusal were not
  reached by a model in these runs.
- **`project_summary.next` (K4)** now reads "The project holds no artifacts
  yet; guide_read lists a playbook for each kind of work". No run created
  work it was not asked for. The cell that was misled by the old hint
  (cad-plate, luna) was not in this re-run.

### Observations (not failures)

- **Codex loaded a plugin from outside the harness's configuration.** The
  astra run's stderr has one line:
  `rmcp::transport::worker: worker quit with fatal: Transport channel closed, when AuthRequired(…"https://codex-app.tldraw.xyz/…")`.
  The server is an app plugin from the account's remote curated catalog.
  Its cache entry under `~/.codex/plugins/cache/openai-curated-remote/` was
  rewritten at 04:20, when this run started. The error came from the child
  started with `--ignore-user-config`, so that flag did not keep the plugin
  out.
  The server failed authentication and offered no tools. The run made 0
  calls outside Omen Flow. In the first pass stderr was empty in all 5 Codex
  runs. So "the person's plugins stay out" was not fully true on Codex
  0.156.1 (README and `run.ts` comment corrected). The harness flags were not
  changed, so this run stays comparable. Before the next Codex run, add a
  Codex override that disables plugins and apps, and verify that no other
  MCP server starts.
- **Provenance of a defaulted input.** The calculation's
  `usable_fraction` input is stored as `{"value": 1, "unit": "1"}` with
  `literal: false` and no `sourceRef`. That it is a default is said only in
  `assumptions` and the reply's `notes`. A reader of the input list alone
  cannot tell it was not given. This is for the core owner to consider; the
  judge does not count it against the run.
- **Skipped trial.** Haiku full committed directly without the trial the
  always-on instruction 5 and `cad-verify` step 2 ask for. The commit
  restored the committed scope and passed, so nothing false was recorded.
- n = 1 per cell. The calculation cell flipped once before, and one pass
  after the fix is still one observation.
